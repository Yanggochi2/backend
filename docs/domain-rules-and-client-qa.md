# 도메인 규칙 재정립 및 클라이언트 확인 목록

기준일: 2026-10-27

## 검토 범위와 우선순위

`docs/01_기획`, `docs/02_명세서`, 초기 회의록과 노션 반입 문서를 다시 검토했다. 문서끼리 충돌하는 경우에는 가장 최근에 전달된 아래 요구를 기준으로 삼는다.

- 병동 인원은 수간호사 1명, 차지 간호사 2명, 일반 간호사 25명으로 구성한다.
- 직급은 `수간호사 > 차지 간호사 > 일반 간호사`이고 경력과 분리한다. 따라서 25년 차 일반 간호사와 23년 차 차지 간호사가 모두 가능하다.
- 프리셉터는 직급이 아니라 일반 간호사에게 부여하는 역할 속성이다. 현재 데이터에서는 입사 연도 기준 5~6년 차 일반 간호사만 지정한다.
- 로그인, 권한 분기, 일반 간호사의 온라인 오프 신청은 제품 범위에서 제외한다. 서비스는 병동 관리자용 단일 화면으로 운영한다.
- 확정된 근무표는 비밀 공유 링크를 발급해 로그인 없이 읽기 전용으로 조회한다. 링크 재발급 시 이전 링크는 만료한다.
- 간호사 입력값은 입사일 대신 입사 연도를 사용하고, 병동 소속 시작일은 별도로 유지한다.

과거 회의록의 “차지는 날짜별 표시”라는 정의는 최신 요구의 직급 체계와 충돌하므로 폐기한다. 다만 각 근무조에 차지 간호사가 반드시 있어야 하는지는 별도 운영 규칙이므로 아래 Q&A에서 확인한다.

## 현재 적용 규칙

| 항목 | 적용 내용 | 상태 |
|---|---|---|
| 최대 연속 근무 | 5일 | 문서 공통값, 클라이언트 최종 확인 필요 |
| 야간 뒤 휴식 | N 다음 날 근무 금지 | 필수 규칙으로 적용 |
| 야간 뒤 추가 휴식 | N 다음 2일째 OFF 권장 | 소프트 규칙으로 적용 |
| 임시 최소 인원 | D 6명 / E 5명 / N 4명 | 목데이터용 임시값, 확정 전 |
| 차지 배치 | 직급 데이터만 사용 | 조별 필수 배치는 확인 전까지 비활성 |
| 프리셉터 동반 | 역할 속성과 연결 관계 저장 | 같은 근무 배치는 확인 전까지 비활성 |
| 희망 근무·오프 | 온라인 신청 기능 제거 | 규칙 입력과 생성에서 제외 |

확정되지 않은 값을 알고리즘의 하드 제약으로 추정하지 않는다. 임시 최소 인원은 초기 화면과 생성 테스트를 위한 값이며, 답변이 오면 규칙 파라미터로 교체한다.

## 클라이언트 Q&A

아래 질문에 답을 받으면 규칙 기본값과 자동 생성 제약을 확정한다.

1. 평일, 주말, 공휴일 각각 D/E/N의 **최소 필요 인원**은 몇 명인가요? 날짜별로 정확히 그 인원이어야 하나요, 최소 이상이면 되나요?
2. 최대 연속 근무는 5일이 맞나요? 교육일이나 연차도 연속 근무 계산에 포함하나요?
3. 최대 연속 N은 3일이 맞나요? 한 번의 N 뒤에도 다음 날 OFF 1일이 반드시 필요하나요?
4. N 뒤 두 번째 OFF는 필수인가요, 가능하면 지키는 권장 조건인가요?
5. E→D, N→D, N→E 전환은 모두 금지인가요? 추가로 금지할 근무 전환이 있나요?
6. D/E/N 각 조마다 차지 간호사가 최소 1명 필요하나요? 차지가 부족한 날에는 일반 간호사 중 대체 가능한 조건이 있나요?
7. 수간호사는 월 근무표 인원과 D/E/N 필요 인원 계산에 포함되나요? 포함된다면 가능한 근무 종류는 무엇인가요?
8. 각 조에 필요한 숙련 간호사 최소 인원은 몇 명인가요? 숙련도 1 간호사는 어느 근무에서 지원 인력이 필요하나요?
9. 프리셉터와 프리셉티는 항상 같은 근무여야 하나요? 필수 규칙인지 권장 규칙인지도 확인이 필요합니다.
10. 임신 중 간호사의 N 금지 외에 연속 근무, E 근무 등에 추가 제한이 있나요?
11. 월별 목표 OFF 수는 공휴일 수와 동일한가요? 중도 입·퇴사자는 어떤 방식으로 일할 계산하나요?
12. 연차(AL), 교육(EDU), 기타 비근무 코드가 필요하다면 각각 필요 인원과 연속 근무 계산에 어떻게 반영하나요?

답변 기록 시 각 항목에 `확정값`, `하드/소프트`, `시행 월`을 함께 남긴다.
