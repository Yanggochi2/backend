# 병동 가입 · 초대 흐름

간호사 계정이 병동에 소속되는 방법과 그 규칙을 정리한다. 코드: `app/business/wards.py`

## 기본 개념

- **계정(User)** 과 **간호사 행(Nurse)** 은 별개다. 근무표·신청·통계는 모두 간호사 행에 붙는다.
- 계정은 간호사 행의 `user_id`로 연결될 때 그 병동에 소속된다. 역할(수간호사/간호사)도 계정이 아니라 행의 속성이다.
- 한 계정은 한 병동에만 소속된다 (🔶 다중 소속 미허용 가정). 가입 대기 신청도 동시에 하나만 둘 수 있다.
- 간호사 행은 두 가지 방식으로 생긴다.
  1. 수간호사가 **계정 없이 등록** (`POST /wards/me/nurses`) — 실제 사람이 아직 가입하지 않은 상태
  2. 가입 신청을 **승인**할 때 새로 생성

## 가입 경로 두 가지

같은 API(`POST /ward-membership-requests {joinCode}`)에 넣는 코드의 길이로 구분한다.

| | 병동 공용 코드 | 개인 초대 코드 |
|---|---|---|
| 길이 | 8자 | 10자 |
| 발급 | 병동 개설 시 자동. `GET /wards/me/join-code`, 재발급 `POST /wards/me/join-code/rotate` | 계정 없는 간호사 행마다 수간호사가 발급 `POST /wards/me/nurses/{id}/invite-code` |
| 대상 | 누구나 (단톡방 공유 등) | 그 행의 본인 한 명 |
| 유효 | 재발급 전까지 | 7일 🔶, **1회용**, 재발급하면 이전 코드 무효 |
| 결과 | `PENDING` → 수간호사 승인·반려 | 승인 없이 그 행에 바로 연결 (`APPROVED`, `via: INVITE_CODE`) |
| 연결되는 행 | 승인 때 `nurseId`를 고르면 그 행, 아니면 새 행 | 코드가 가리키는 행 |

**어느 쪽을 쓰나:** 수간호사가 명단을 미리 등록해 뒀다면(엑셀 일괄 등록 포함) 개인 초대 코드를 쓴다. 근무표·신청이 처음부터 그 행에 붙고, 같은 사람이 두 행이 되는 일이 없다. 명단에 없는 사람은 공용 코드로 신청받아 승인한다.

## 흐름

```
[공용 코드]  가입 신청 ──> PENDING ──(승인)──> APPROVED  ── 새 행 생성 또는 nurseId 행에 연결
                          │  └────(반려, 사유 필수)──> REJECTED  ── 신청자에게 알림
                          └──(신청자 본인 취소 / 초대 코드로 다른 병동 가입)──> CANCELLED

[초대 코드]  수간호사가 행에 코드 발급 ──> (7일 안에) 간호사가 코드 입력 ──> APPROVED, 행에 즉시 연결
                 │                                                       └─ 수간호사 전원에게 MEMBER_JOINED 알림
                 └─ 재발급 / 취소(DELETE) / 퇴사 처리 / 병동 탈퇴 / 만료 ──> 코드 무효

[잘못 연결]  수간호사가 계정 연결 해제 ──> 행은 재직 그대로, 계정만 떨어짐 ──> 새 초대 코드로 올바른 사람 연결
```

## 규칙

**가입 신청 (공통)**
- 이미 병동에 소속된 계정은 신청할 수 없다 → 409 `MEMBERSHIP_ALREADY_EXISTS`
- 코드 입력은 계정당 시간당 10회 🔶 → 초과 시 429. 대소문자 무시
- 없는 코드 → 404 `JOIN_CODE_NOT_FOUND`

**공용 코드**
- 대기 신청이 이미 있으면 → 409 `REQUEST_ALREADY_EXISTS`. 신청자 본인이 `DELETE /ward-membership-requests/me`로 취소할 수 있다 (코드를 잘못 넣은 경우 등). 내 신청 상태는 `GET /me`의 `membershipRequest`
- 대기 중에는 병동 개설도 막는다. 나중에 승인되면 두 병동에 소속되기 때문
- 승인으로 부여되는 역할은 항상 `NURSE`. 수간호사 권한은 권한 부여·이관(AUTH-07)으로만

**승인 시 기존 행에 연결 (`nurseId`)**
- 가입 대기 목록의 `candidates` = 이름이 같고 계정이 없는 재직 간호사 행. **유효한 초대 코드가 나가 있는 행은 제외**한다
- 연결 대상은 같은 병동의 계정 없는 재직 간호사여야 한다 → 아니면 404 / 422 `NURSE_NOT_LINKABLE`
- 유효한 초대 코드가 나가 있는 행에는 연결할 수 없다 → 409 `INVITE_CODE_OUTSTANDING`. 코드를 받은 사람이 따로 있기 때문. 그 사람이 코드로 가입하게 하거나, 코드를 취소한 뒤 연결한다
- 연결하면 그 행에 남아 있던 (만료된) 코드도 지운다

**초대 코드**
- 발급 대상은 같은 병동의 계정 없는 재직 간호사 행 → 연결된 행 409 `NURSE_ALREADY_LINKED`, 퇴사자 422 `NURSE_NOT_ELIGIBLE`
- 코드는 발급 응답에서만 보인다. 잃어버리면 재발급한다. 간호사 응답의 `inviteExpiresAt`(수간호사만)으로 발급 여부·만료를 확인한다
- 만료된 코드 → 422 `INVITE_CODE_EXPIRED` (수간호사에게 재발급 요청)
- 코드로 가입하면 그 계정의 다른 대기 신청은 자동 취소된다
- **승인 단계가 없으므로 수간호사 전원에게 알린다.** 계정 이름이 행의 이름과 다르면 알림에 계정 이름을 적어 확인을 요청한다 (코드가 다른 사람에게 넘어간 경우를 알아차리기 위함)
- 코드가 다른 사람에게 넘어갔다면 `DELETE /wards/me/nurses/{id}/invite-code`로 취소한다. 이미 그 사람이 가입했다면 아래 "계정 연결 해제"

## 잘못 연결된 계정 되돌리기

`POST /wards/me/nurses/{id}/unlink-account {reason}` (수간호사)

초대 코드가 다른 사람에게 넘어갔거나, 승인 때 다른 사람의 행을 고른 경우에 쓴다. 퇴사 처리와 달리 **행은 재직 상태 그대로** 남는다.

- 행의 `user_id`만 비운다. 근무표·지난 이력은 그대로
- 그 계정이 이 행으로 낸 **대기 중인** 신청은 취소한다 (승인된 신청은 수간호사가 판단한 것이라 둔다)
- 그 계정이 쥔 근무표 편집 잠금을 푼다
- 수간호사였더라도 권한은 남기지 않는다 (`NURSE`로)
- 해제된 계정에게 사유와 함께 알린다. 그 계정은 소속이 없어져 다른 병동에 가입할 수 있다
- 이후 그 행에 새 초대 코드를 발급해 올바른 사람을 연결한다
- 사유 필수 400 `REASON_REQUIRED` · 본인 409 `CANNOT_UNLINK_SELF`(병동 탈퇴 이용) · 계정 없는 행 409 `NURSE_NOT_LINKED` · 퇴사자 422 `NURSE_NOT_ELIGIBLE`

## 탈퇴

- 병동 탈퇴(`POST /wards/me/membership/leave`)는 간호사 행을 지우지 않는다. 퇴사 처리 + 계정 연결 해제만 하므로 지난 근무표·감사 로그가 남는다
- 탈퇴하면 그 행의 초대 코드도 무효. 마지막 수간호사는 권한 이관 후에만 탈퇴할 수 있다
- 탈퇴한 계정은 다시 아무 병동에나 가입할 수 있다

## 감사 로그

| 행위 | action |
|---|---|
| 공용 코드 신청 / 승인 / 반려 / 본인 취소 | `MEMBERSHIP_REQUESTED` / `MEMBERSHIP_APPROVED` / `MEMBERSHIP_REJECTED` / `MEMBERSHIP_CANCELLED` |
| 공용 코드 발급·재발급 | `JOIN_CODE_ISSUED` |
| 초대 코드 발급 / 취소 | `INVITE_CODE_ISSUED` / `INVITE_CODE_REVOKED` |
| 초대 코드로 가입 | `MEMBERSHIP_JOINED_BY_INVITE` (after에 가입한 계정 이름) |
| 계정 연결 해제 | `MEMBER_UNLINKED` (before에 계정 이름·역할, after에 사유·취소한 신청 수) |

## 🔶 결정 필요

- 초대 코드 유효 기간 (현재 7일)
- 공용 코드 승인 시 `nurseId` 연결 옵션은 초대 코드가 정착하면 없앨 수 있다
