# 근무표 자동 생성기 재작성 (CP-SAT) 설계

- 날짜: 2026-10-26
- 대상: `app/domain/generator.py` (GEN-01), 규칙 목록(RULE-01), 검증기(SCH-06)
- 기준 브랜치: `feat/schedule-flow` (PR #70)

## 배경

지금 생성기는 날짜순 그리디라서 월 OFF 목표, 주말·공휴일 공정성, 근무 순환 모양을 보지 않는다. 30명 데이터에서 `N OFF N OFF` 같은 들쭉날쭉한 배치가 나오고, 최적해도 보장하지 않는다(이슈 #26). 실제 간호사 근무표 규칙을 조사해 기준을 다시 정하고, 그 기준으로 OR-Tools CP-SAT 생성기를 만든다.

## 규칙 기준 (조사 결과)

근거: 보건복지부「간호인력 야간근무 가이드라인」(2019, 권고), 근로기준법 제59조 2항(보건업 특례 시 근무 사이 11시간 연속 휴식), 서울대병원 노조 단체협약 제4장(야간 월 6일 이하, 가능한 한 주 2일 연속 휴일), 4개 병원 단협 분석 연구(연속 근무 최대 5일, 연속 야간 3~4일, 월 야간 7일 이내), 보건의료노조 2021 실태조사(월 야간 6~7회에 집중), 야간근무 실태 연구(월 평균 야간 6.1일).

### 하드 (생성 결과가 반드시 지킨다)

| 코드 | 내용 | 비고 |
|---|---|---|
| COVERAGE | 근무별 필요 인원 충족 | 인원 부족 달 대비 큰 감점 여유 변수로 모델링 (아래) |
| NIGHT_TO_DAY | 역순환 금지: E→D, N→D, N→E | 기존 코드 유지, 의미를 넓히고 표시 이름을 "역순환 금지"로 변경 |
| MAX_CONSECUTIVE_NIGHTS | 연속 야간 최대 (기본 3) | 기존 |
| NIGHT_REST | 야간 2일 이상 연속 후 OFF 2일 | **신규** |
| MAX_CONSECUTIVE_WORK | 연속 근무 최대 (기본 5) | 기존 |
| PREGNANT_NIGHT, OUT_OF_AFFILIATION | 임신 중 야간 금지, 소속 기간 밖 배정 금지 | 기존 |
| CHARGE_DAY_ONLY, NEW_NIGHT_ALONE | 차지는 D만, 신입 단독 야간 금지 | 기존. NEW_NIGHT_ALONE은 큰 감점 여유 변수 |
| (입력) | 승인된 연차(AL)·고정 셀(GEN-05) | 값 고정 |

### 소프트 (감점 점수로 최대한 맞춘다)

| 코드 | 내용 | 가중치 |
|---|---|---|
| WISH_OFF_IGNORED | 승인된 희망 오프 미반영 | 40 / 일 |
| MAX_MONTHLY_NIGHTS | 월 야간 상한 초과 (기본 6) | 50 / 회 | **신규** |
| OFF_TARGET | 월 OFF 목표 부족 (주말 수 + 공휴일 수) | 30 / 일 |
| NIGHT_OFF_DAY | N→OFF→D ("나오데") | 20 / 회 | **신규** |
| WISH_DUTY_IGNORED | 희망 근무 미반영 | 20 / 일 |
| WEEKLY_REST | 연속 OFF 2일이 없는 주 | 15 / 주 | **신규** |
| ISOLATED_SHIFT | 고립 배치: OFF-근무-OFF, 근무-OFF-근무 | 10 / 회 | **신규** |
| PRECEPTOR_MISMATCH | 프리셉터와 담당 신입의 근무 불일치 | 5 / 일 |
| (공정성) | 간호사 사이 야간·주말 근무·총 근무 횟수의 최대-최소 차이 | 10 / 차이 1 |

가중치는 코드 상수로 두고 병동 설정으로 노출하지 않는다. 규칙의 켜기/끄기와 HARD/SOFT 전환은 기존 규칙 화면이 그대로 다룬다. HARD로 켜진 규칙만 제약으로 걸고, SOFT로 바뀐 하드 규칙은 큰 감점(500)으로, 꺼진 규칙은 무시한다.

## 규칙 목록 변경

- `app/business/rules.py` CATALOG에 신규 5개(NIGHT_REST, MAX_MONTHLY_NIGHTS(params `{"max": 6}`), NIGHT_OFF_DAY, ISOLATED_SHIFT, WEEKLY_REST)를 추가하고, NIGHT_TO_DAY 표시 이름을 "역순환 금지 (E→D, N→D, N→E)"로 바꾼다.
- 기존 병동에는 새 규칙 행이 없다. `rules.rows()`가 CATALOG에 있고 DB에 없는 규칙을 프리셋 기본값으로 만들어 넣는다(지연 백필). 마이그레이션 불필요.
- MINIMAL 프리셋은 신규 하드 규칙(NIGHT_REST)도 끈다.
- `Rules` 모델에 `max_monthly_nights`를 추가한다.

## 검증기 (SCH-06)

`app/domain/validator.py`가 신규 규칙 위반과 넓어진 역순환(E→D, N→E)을 보고한다. 생성기와 검증기는 같은 규칙 정의를 기준으로 한다. 공정성은 위반 항목이 아니다.

## 생성기 (`app/domain/generator.py`)

- 시그니처 유지: `generate(r: Roster, max_seconds: float = 10) -> Cells`. 호출부(`generations.py`)는 `max_seconds`만 넘기도록 바뀐다.
- 변수: 간호사 × 날짜 × {D, E, N, O} 불리언. 날마다 정확히 하나. AL·고정 셀·소속 기간 밖(셀 없음)·휴직자(O)는 값 고정.
- 지난달 말 근무(`Roster.before`)를 상수로 이어 붙여 연속·역순환·야간 휴식을 월 경계 너머로 계산한다.
- 고정된 칸끼리만으로 이미 어긋나는 구간(예: 지난달 말 근무와 이어지는 구간)은 제약에서 뺀다. 그런 구간 때문에 모델 전체가 해 없음이 되지 않게 하기 위함이다. 그 위반은 검증기가 보고한다.
- COVERAGE와 NEW_NIGHT_ALONE은 부족분 여유 변수에 가중치 10000을 붙인다. 인원이 부족한 달에도 결과가 나오고, 남은 하드 위반은 검증기가 잡아 기존 "해 없음 → 완화안"(GEN-04/06) 흐름을 탄다.
- 공정성은 소속 기간이 그 달 전체이고 휴직이 아닌 간호사만 대상으로 한다.
- 솔버: 시간 제한 `max_seconds`(기본 10, API로 1~60), `num_workers=8`, `random_seed` 고정(같은 입력이면 같은 결과). 시간 안에 해를 못 찾으면(이론상 여유 변수 때문에 드묾) 기존 그리디로 대체한다.
