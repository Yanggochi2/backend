# 10/26 회의 반영 백엔드 작업 계획

기준: 사용자가 제공한 2026-10-26 회의록. 기존 명세와 충돌하면 이 회의록을 우선한다.
기준 커밋: backend 2478660. 작업 브랜치: feature/client-1026-backend.

| 순서 | 작업 (백엔드 구현 완료) | 수용 기준 |
|---|---|---|
| 1 | 수간호사 계정 편집, 일반 간호사 신청 API 제거 | 로그인한 수간호사만 관리 API 접근. 일반 간호사는 공유 링크 조회만 가능 |
| 2 | 공유 링크 발급·교체·폐기 | 확정본만 읽기 가능. 조회 토큰으로 수정 불가. 교체·폐기·확정 취소 시 옛 링크 차단 |
| 3 | 간호사 등록·수정과 정렬 | joinedYear 입력, 소속 날짜 유지. 수간호사→차지→일반, 각 그룹 경력 내림차순. 이름순 지원 |
| 4 | 도메인·생성기 수정 | 차지는 평일 D/주말·공휴일 O. 프리셉터는 직급과 별도. 월 O = 주말∪공휴일 + 1. E/N 독립 배분 |
| 5 | 데모 데이터 | 수간호사 1 + 차지 2 + 일반 25, 5~6년차 프리셉터, 고경력 일반·차지 혼합 |
| 6 | 회귀·통합 검증 | 불가능한 편성은 원본 보존, 고정 연차/교육 보존, 월 경계 규칙, 병동 격리, 공유 개인정보 최소화 |

## 적용 가정과 클라이언트 확인 항목

- 편집 전용 비밀 링크 + 공개 조회 링크: 사용자 확인 완료. 관리 토큰은 헤더로 전달하고 DB에는 해시만 저장한다.
- 차지는 주5일 근무 기준이 우선하므로 추가 1일 O를 강제로 만들지 않는다. 공휴일에는 휴무한다.
- 수간호사도 우선 평일 D·주말/공휴일 O로 적용한다. 직접간호 필요 인원에 포함할지는 확인 필요(현재 포함).
- 일반 간호사 O 목표는 주말과 공휴일의 합집합 크기 + 1. AL(연차)과 ED(교육/학회)는 O로 세지 않는다.
- 필요 D/E/N은 최소 인원으로 해석한다. O 목표를 맞추기 위한 추가 근무는 D를 우선하고 불필요한 E/N 증가는 감점한다. 정확한 정원/상한 여부 확인 필요.
- 중도 입·퇴사자는 O 목표를 소속 일수로 비례 계산(반올림), 휴직자는 전체 O. 운영 기준 확인 필요.
- 자동 공휴일은 기존 양력 목록 + 병동 보정값. 설/추석/대체/임시공휴일은 관리자가 입력해야 하며 자동 수집은 별도 작업이다.
- 프리셉터 지정에 경력 상·하한을 하드코딩하지 않는다. 5~6년차는 데모 구성 기준이다.
- 월간 초기 화면, 정렬 선택 UI, 수간호사 로그인, 일반 간호사 신청 화면 제거, 등록·수정 폼 공유, 공유 화면은 프론트엔드 연동 작업이다.

### 미결정 사항의 처리 원칙

- D/E/N 필요 인원의 최소/정확 기준, 수간호사의 직접간호 인원 포함 여부, 차지의 추가 O 1일, 중도 입퇴사자의 O 계산은 클라이언트 결정이 필요하다.
- 답변 전에는 현재 구현을 유지한다. 답변 후 코드를 다시 갈아엎지 않도록 병동 설정으로 분리하고 변경 이력을 감사 로그에 남기는 방향을 권장한다.
- 공휴일 자동 연동은 공식 데이터의 연도별 캐시, 병동 보정 우선, 외부 장애 시 마지막 정상 데이터 사용을 기준으로 별도 구현한다.
- 운영 전에는 실제 PostgreSQL 마이그레이션·복구와 다개월 생성 품질 검증을 완료해야 한다.
- 선택지, 권장 검토안, 검증 지표, P0~P2 발전 계획의 전체 내용은 docs 저장소의 `05_할일/백엔드_미결정사항_및_발전로드맵.md`를 기준으로 관리한다.

## 데이터 전환

기존 데이터 삭제 없이 추가 테이블과 is_preceptor 컬럼만 마이그레이션한다. 기존 입사일은 보존하고 API에는 연도만 노출한다. 기존 인증/신청 기록은 보존하지만 HTTP 경로는 제거한다. 기존 병동에는 운영자 CLI로 관리 링크를 발급한다. 기존 규칙값을 자동 덮어쓰지 않으며 새 규칙 기준 전환은 별도 명령으로 명시적으로 수행한다.
